# CPlayer 5 项目优化方案

制定日期：2026-09-27。基于当前工作区的源码核查及 269 项通过的测试基线。

配套阅读：[项目梳理与优势说明](PROJECT_OVERVIEW.md)。本文件是实施建议，不表示下列优化已经完成。

## 1. 优化目标与边界

目标：让“找到音乐并稳定播放”成为最清晰的产品主线，同时降低持续迭代、发布和第三方接口维护成本。

基本原则：

- 保留原生 JavaScript 和现有测试，按职责逐步拆分，不先做全量框架迁移。
- 优先解决用户可感知的问题与发布风险，不先扩张音源或堆叠动效。
- 不把 PWA 外壳缓存宣传成离线听歌，不把上游音质标签当作音频质量鉴定。
- 不绕过登录、付费、下载限制或平台风控；公开访问不等于获得再分发许可。
- 本轮只整理文档；以下代码改造需在后续实施中开展。

优先级定义：P0 为下一次公开发布前建议完成的基线工作，并不表示已确认严重漏洞；P1 为主要体验和维护收益；P2 为按测量结果推进的增强项。

## 3. P0：先建立可信的产品与发布基线

### O1. 统一产品定位、真实能力与命名

改造范围：`README.md`、`manifest.json`、主页面文案、关于页、开发文档、社交分享元数据。

实施建议：

1. 明确“CPlayer 5”是项目名称，“505音乐之家”是否为部署站点名称。若二者保留，写清关系，不必未经确认直接改名。
2. 统一为实际支持的五档网易云音质；准确注明当前默认 `lossless`、上游可用性、自动降级和 Bilibili AAC 区别。
3. 校准离线、歌词缓存、YRC、动态背景和 Wake Lock 说明。未接通能力移到计划列表，不继续作为已完成功能宣传。
4. 开发文档统一到 `npm run build` + `npm start`；`.env.example` 仅是模板，当前 `server.js` 不会自动加载 `.env`，应明确环境变量注入方式。
5. 建立单一发布版本来源，区分产品版本、静态资源哈希和缓存版本。

验收：README、页面、PWA 和开发文档对同一功能无互相矛盾的描述；新开发者按文档可启动同源服务；不再出现“放入 `.env` 就一定生效”的隐含假设。

### O2. 补齐构建产物和真实服务验证

已确认的结构风险：`scripts/build_sites.sh` 向已有目录复制文件，源码移除某资产或可选 `playlist.js` 后，旧构建目录可能继续保留它；当前 CI 探测源码目录的静态 HTTP 服务，无法覆盖 `/api/*` 和无后缀页面路由。

实施建议：

- 在明确的临时输出目录生成完整产物，校验后再替换发布目录；仅处理构建输出，不删除源码或用户资料。
- 对产物执行静态资源校验，验证引用闭包以及不包含 `.env`、密钥、测试输出等非发布内容。
- CI 显式固定并验证 Node/Python 版本，执行测试、构建、产物校验和 Node 服务冒烟。
- 冒烟覆盖 `/`、`/playlist-downloader`、`/offline`、`/sw.js`、`/manifest.json`、API 参数错误及缺密钥错误；上游成功/失败路径使用受控 fixture，避免 CI 依赖实时平台。
- 验证社交元数据替换后的响应头、音频 Range/HEAD、客户端断开和静态路径限制。
- 为 JS/CSS/fonts 的 Content-Type 增加断言，尤其当前 TTF 不在 Node 服务的显式 MIME 表中。

验收：同一源码连续构建得到同一文件集合；移除输入资源后旧资源不再进入发布包；完整服务在无密钥时给出预期错误而不泄漏配置；保留上一版产物以便回滚。

### O3. 上游、部署安全与素材合规

保留既有 ID/域名白名单、下载权限检查、禁止任意 URL 中继、密钥后置等控制，在部署层补充：

- 明确接口密钥配额、超时预算、上游不可用提示和日志脱敏规则；不要记录包含密钥的完整上游 URL。
- 公网开放时先在反向代理或部署平台配置访问速率、音频并发和带宽限制。实例级 350 ms 排队、30 秒退避不等于全站限流；只有多实例需求成立时再引入共享配额存储。
- 评估网易云元数据请求和内容请求的共享短缓存/在途合并；按来源、ID、音质区分键，不长期缓存签名音频 URL。
- 对主题角色、图标、字体、截图和第三方库建立来源与许可台账；目前第三方说明主要记录 oneko，不能代表其他素材已核实。无法确认授权的角色素材在公开发布前换成原创或明确授权版本。
- 安全响应头先做兼容性清单；CSP 先 Report-Only 验证，外置脚本/移除运行时样式编译后再逐步收紧，避免直接破坏播放器与合法媒体请求。

验收：缺密钥、429、超时、内容受限均有可理解的提示；日志无凭据；限流/并发措施在实际部署层可验证；授权不明素材有明确处理决定。平台条款与使用许可由项目方确认，不以技术可访问替代。

## 4. P1：围绕主流程改善体验与结构

### O4. 统一产品信息层级和失败恢复

建议首页突出：搜索/音源选择 → 最近可播放内容或发现入口 → 榜单/场景歌单；常驻播放器持续显示歌曲、来源、真实播放状态与队列入口。

状态统一为：空、加载中、成功、部分成功、使用旧快照、无权限、限流、网络失败。按音源能力显示控件，Bilibili 不出现会误导的 FLAC/母带选择。

`js/http.js` 当前遇到非成功状态会抛 HTTP 状态错误，不读取后端结构化错误体。建议限定解析 `{ error: { code, message } }`，通过允许的错误码映射文案与恢复动作，避免将服务未配置、上游鉴权失败、普通网络故障都显示成同一种失败。不要直接展示未过滤的上游内容。

播放反馈明确区分“请求音质”与“实际返回音质/格式”；现有下一首预加载可宣传减少等待，但在跨曲实测前不称为严格无缝播放。

验收：首次用户能清楚找到搜索/导入入口；离线、空队列和上游失败均有下一步操作；降级音质、快照时间和字幕来源不靠颜色单独表达；桌面和手机使用同一套状态语义。

### O5. 按业务职责渐进拆分主页面

建议目标边界（是提案，不是当前已有目录）：

```text
js/
  services/music-service.js       音源路由与规范化调用
  player/playback-controller.js   音频状态、切歌、音质、系统媒体控制
  player/queue-store.js           队列、播放顺序、撤销
  player/lyrics-controller.js     歌词解析、时间索引、渲染更新
  storage/cache-store.js          IndexedDB 生命周期、限额与错误降级
  ui/mobile-controller.js        移动手势与抽屉
  app.js                         初始化和模块连接
```

实施顺序：先提取无 DOM 的纯逻辑和存储边界，再提取服务与播放控制，最后搬 UI。沿用已有 session 模块，不重复创建全局状态框架。

每一步保持 DOM ID、事件契约和原有交互不变；将相关测试从截取 HTML 字符串逐步迁移为直接导入模块。模块名和文件数按实际职责调整，不为达到行数目标而机械拆文件。

验收：每次拆分后现有测试与新增行为测试通过；旧请求不能覆盖新歌/音质/歌词；入口以编排为主；关键逻辑可脱离页面独立测试。保留小步提交，出现回归可逐步撤回。

### O6. 收敛多代样式，形成单一设计规则

先以当前最终 Studio 风格为核查基准，盘点 `index.html` 内联样式、`app-shell.css`、`art-direction.css`、`bilibili.css`、`studio.css` 的有效规则。

统一颜色、字号、间距、圆角、层级、焦点、动效令牌，明确基础 → 布局 → 组件 → 主题的覆盖顺序。只在确认无引用并通过视觉回归后移除旧规则与旧背景代码，不直接批量删除 `!important`。

保留有辨识度的像素猫/交互挂件，但提供隐藏和减少动态效果的清晰入口，不遮挡播放器、移动底部操作和键盘焦点。

验收：390px、768px、1024px、1440px 等代表宽度在昼/夜主题下无关键遮挡和横向溢出；键盘焦点可见；普通文字对比度以 WCAG AA 为目标，结合自动检查和人工核查，而非只依靠源码断言。

### O7. 资源和加载优化

已测量的原始文件基线：主 HTML 428,269 字节，Tailwind Runtime 407,279 字节，四个 TTF 总计 42,126,576 字节。它们是磁盘原始体积，不是压缩传输量，也不等于首屏实际加载量。

建议步骤：

1. 用真实浏览器记录请求瀑布、压缩传输量、JS 执行和字体实际使用，建立前后对照。
2. 将 Tailwind 改为构建期生成 CSS，扫描 HTML 与 JS 中的类名；对动态拼接类设置明确保留规则，防止构建后样式缺失。可增加构建依赖，但不引入运行时框架。
3. 当前优先使用系统字体，若无品牌字体要求可减少随包字体；若保留，评估 WOFF2/分片和许可，不能随意裁掉歌名可能出现的字形。
4. 对未使用的 Font Awesome 文件、旧社交图等先做引用和部署用途核查，再决定不纳入产物；明确移除理由，不按大小盲删。
5. 在现有内容懒加载基础上，按页面需求加载非关键模块；将图形和挂件作为可选增强。
6. 通过部署层启用 Brotli/gzip；引入内容哈希后静态资产长期缓存，HTML/SW 使用适合升级的策略。

验收：生产页面不再加载 Tailwind Runtime；动态类样式无丢失；产物不夹带确认未使用的资源；同设备同网络条件下首屏压缩传输目标比基线降低至少 30%，若基线不支持该目标则依据测量调整并说明原因。

### O8. 缓存治理与安全升级

- 保持 API、音频不进入 Service Worker 通用缓存，避免签名过期、权限混淆和存储膨胀。
- 区分偏好、榜单快照、歌单数据、封面；设置版本、容量、时间戳、过期与淘汰策略。
- SW 封面已有 100 条上限；IndexedDB 图片/歌单还应补容量与淘汰机制，处理配额不足、私密模式和数据库不可用。
- 对歌词缓存做明确取舍：删除未实现宣传，或实现按 `provider + sourceId + language` 区分的读写、TTL 和清理，避免音源 ID 冲突。
- 设置中提供缓存占用、清理内容缓存和完整重置的区别；普通清理不丢偏好或用户歌单。
- 当前 SW 使用 `skipWaiting`/`clients.claim`，资产手工版本混用；建立旧页与新资源兼容策略，提示可更新，并在合适时机刷新，避免打断播放。

验收：缓存命中、过期、存储满和不可用均有测试；新旧版本、多标签页和离线重启可验证；旧快照显示更新时间；更新不会无提示丢队列或中断当前播放。

### O9. 浏览器测试与可观测性

保留现有单元/契约测试，增加真正通过页面入口操作的浏览器测试：

1. 空状态 → 搜索 → 加入队列 → 播放 → 进度跳转。
2. 快速切歌/切音质，旧封面和歌词迟到。
3. 网易云与 Bilibili 混合队列、跨源切换和来源标记。
4. 导入成功、格式错误、超大文件；删除、清空、撤销。
5. 下载允许/拒绝、取消、重开对话框与请求失败。
6. 桌面/移动切换、键盘导航、焦点恢复、减少动态效果。
7. 页面断网、上游限流、旧快照与 SW 更新。

使用合法的小型本地媒体与 API fixture 保证确定性；涉及 SW 的升级/缓存测试必须开启 SW，不能用禁用 SW 的通用 fixture 代替。实时上游检查作为独立、低频、经授权的环境验证，不成为每次提交的外部依赖。

观测先从最少信息开始：失败分类、上游耗时、点击播放到 `playing` 的时长、缓存命中、流连接数；区分取消请求与真正失败。不默认收集歌名、搜索词、完整播放 URL、Cookie 或个人播放历史。

验收：主要流程可在 CI 重复运行；失败可区分浏览器策略、站点错误和上游限制；有实测基线而非“体验很快”的主观判断。

## 5. P2：基于实际需求做增强

- 大文件下载：现有 `saveAudioBlob` 会完整读入内存；先测真实峰值，再按浏览器能力选择附件直下或可取消流式保存。不得用任意 URL 代理绕过跨域或授权限制。
- 系统集成：如果确需浏览器保活，再通过能力检测接入标准 Screen Wake Lock，处理释放/恢复，允许用户关闭；不能承诺网页在所有平台永久后台播放。
- 节能：根据可见性、系统减少动态效果和用户选择控制可视化/挂件；已有后台停止机制应保留。
- 留存：优先评估本机最近播放、明确的本地收藏与备份，再决定是否需要账号与跨设备同步；不提前搭建完整用户系统。
- 音源扩展：只有在获得可持续访问/使用条件后再接入；先稳定当前两个音源。

## 6. 实施节奏与依赖

以下为单人熟悉代码、接口和设计需求基本稳定时的粗略工程估算，不是已批准排期；素材授权与第三方变更时间另计。

| 阶段 | 建议工作 | 工作量参考 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| A：发布基线 | O1、O2、O3 首轮核查，建立 O9 基础浏览器冒烟 | 3–5 人日 | 文档准确、产物可验证、主要服务路径可重复测试 |
| B：主流程与结构 | O4、O5 第一批拆分、O6 视觉基线 | 5–8 人日 | 播放/队列/歌词契约稳定，关键跨端交互有回归保护 |
| C：性能与维护 | O7、O8、O9 完善，O6 清理收敛 | 5–8 人日 | 有前后性能对照、升级验证和可回滚发布 |
| D：按需增强 | O10 及剩余优化 | 单独估算 | 基线稳定且有用户需求或实测瓶颈支持 |

依赖顺序：先有基线测试，再拆逻辑/样式；先确定动态类和当前视觉，再替换 Tailwind Runtime；资源版本与 SW 升级策略一起设计；上游生产验证和授权核查不能用单元测试替代。

## 7. 指标与最终验收

下列数值是建议目标，不是当前实测成绩。正式实施时固定设备、浏览器、网络与 fixture，并至少进行多次重复测量。

| 维度 | 建议目标/验收方式 |
| --- | --- |
| 回归 | 当前 269 项基线保持通过；重构后的替代测试覆盖同一行为，不以保留旧源码字符串为目标 |
| 真实交互 | 浏览器关键流程稳定通过，至少覆盖 Chromium 和一个 WebKit 环境；移动实机另外抽检 |
| 竞态 | 连续快速选歌/切音质场景中，旧响应覆盖当前状态的次数为 0 |
| 首屏 | 受控移动测试争取 LCP ≤ 2.5s、CLS ≤ 0.1；有真实用户数据后评估 p75 INP ≤ 200ms |
| 首播 | 受控音源测点击至 `playing` 的 p50/p95；实网上游单列，不把上游延迟算成前端优化成果 |
| 体积 | 无 Tailwind Runtime；已确认无用资产不进包；压缩传输量有前后差异报告 |
| 缓存升级 | 离线打开外壳、配额失败降级、多标签页升级、当前播放保护均验证 |
| 安全与合规 | 客户端和日志无密钥；白名单和权限回归通过；公开使用素材来源可追溯 |
