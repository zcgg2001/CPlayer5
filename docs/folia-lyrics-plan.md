# CPlayer5 · Folia 歌词能力升级计划

日期：2026-11-09。状态：Web 核心实现已落地，完整上游视觉/参数对照仍未完成。下文保留原始计划；实际交付与验证见 [实施记录](lyrics-validation.md)。

目标：在 CPlayer5 主播放器内实现 Folia 的 Web 歌词体验，包括真实逐字同步、独立舞台排版、17 种歌词模式、背景组合、模式参数、歌词来源管理与移动端适配。以实际行为和播放效果验收。

## 1. 调研结论

目前 CPlayer5 已有 20 个效果选项：17 个 Folia 对应模式，加普通、AMLL、跃音。现有 `docs/lyric-effects.md` 明确说明，它们是 DOM / SVG / CSS 视觉适配版，没有完整复现原项目的逐字时间轴、3D 场景、音频分析或场景参数。

已核对的关键代码：

| 位置 | 当前行为 | 升级切入点 |
| --- | --- | --- |
| `js/music-data.js`、`sites/channel-providers.js` | 部分链路已经保留 `yrc` 字段 | 先把已有逐字数据送到渲染层，并逐渠道核对真实返回能力 |
| `index.html` 的 `onLyrics` | 只向 `parseLyrics` 传入 `lrc`、`tlrc` | 保留原始格式、来源和逐字信息 |
| `index.html` 的 `parseLrc` / `parseLyrics` | 生成行级 `time/text/translation`，翻译按时间容差匹配 | 抽出统一解析与对齐模块 |
| `index.html` 的 `updateLyrics` | 由播放进度更新触发，使用固定 `time + 0.3` 选中一行 | 分开“提前入场”和“真实演唱进度”，接入统一媒体时钟 |
| `js/lyric-effects.js` | 提供换句装饰、模式切换、字号和三句循环预览 | 改为有时间、数据和生命周期输入的模式宿主 |
| `js/lyric-scenes.js`、`js/lyric-composition.js` | 主要在当前行内部创建场景和排版 | 为舞台模式提供独立容器和跨句过渡 |
| `js/listening-room.js` | 已有阻尼跟随、手动浏览和恢复跟随 | 作为列表歌词模式的基础复用 |
| `index.html` 的 `setupAudioContext` | 已有音频节点和 analyser | 复用频谱与能量数据，避免重复连接媒体源 |
| `scripts/build_sites.sh`、`vite.config.js` | 前端资源主要直接复制，Vite 当前用于 Worker | 引入第三方渲染库时增加独立前端模块打包步骤 |

Folia 当前源码列出 17 个内置歌词模式、6 类背景。官方使用指南部分页面仍写 15 种，实施时以固定提交的源码清单为准，避免用旧文档数量做验收。

## 2. 推荐技术路线

在 CPlayer5 内增加独立的歌词运行模块，继续使用原生 ES modules 连接现有播放控制器。DOM / CSS 负责文字排版和交互；Canvas / WebGL 按复杂模式需要加载。先完成时间轴和一个模式的纵向贯通，再扩展模式数量。

建议的数据流：

```text
现有音乐接口 / 本地歌词文件
          ↓
格式解析 → 数据校验 → 翻译/罗马音/和声对齐
          ↓
统一歌词文档 + audio.currentTime + 已有音频分析 + 主题配置
          ↓
歌词宿主：列表视图 / 舞台视图 / 设置预览
          ↓
模式渲染器 + 背景渲染器
```

宿主负责加载、换曲、播放状态、跳转、尺寸与资源释放；每个模式只负责自己的布局、动画及参数。设置预览使用相同渲染器和固定测试时间轴。桌面、手机共享数据，只让可见的主视图持续渲染。

Folia 仓库标注 AGPL-3.0，当前 CPlayer5 标注 MIT。本计划采用按功能规格独立实现的路线；若后续选择直接移植上游源码或素材，需要另行整理来源、许可及项目分发方式。

## 3. 分阶段实施

### P0：建立对照基线

- 固定 Folia 参考提交，记录 17 个模式、6 类背景及每个模式的参数清单。
- 使用相同歌词、时间点、画面比例录制参考片段，建立“布局、入场、逐字、退场、背景、参数”对照表。
- 准备真实逐字、行级、中英日混排、长句、翻译、罗马音、和声、长间奏、纯音乐等测试素材。
- 核对当前音乐渠道实际返回的逐字数据；记录“接口无数据”和“前端丢失数据”的区别。
- 确认模块打包方式；复杂渲染依赖单独打包、按需加载，纳入现有静态资源构建。

交付：参考清单、素材集、渠道能力表。每个模式都有明确的待实现行为。

### P1：统一歌词数据和媒体时钟

- 将内联歌词逻辑抽到 `js/lyrics/`；统一使用毫秒保存行、词的起止时间，在媒体接口边界转换单位。
- 文档保留：行 ID、起止时间、原文、词级时间、翻译、罗马音、可选演唱者/和声、来源、原始格式、偏移。
- 首先支持 LRC、增强 LRC、YRC；随后接 TTML、VTT、QRC、KRC。压缩或加密容器与已解码歌词分开处理，并用真实文件验证。
- 数据必须保留停顿、重叠行和和声；重复时间戳不能直接把不同声部合并。缺少角色信息时不推断真实演唱者。
- 纯 LRC 按行展示；如果提供平滑扫亮，将其作为可选展示效果，与真实逐字数据区分。
- 用 `requestAnimationFrame` 采样真实 `audio.currentTime`；暂停、缓冲、跳转、倍速、后台恢复均从媒体状态重新定位。
- 将当前固定提前 300 ms 拆成可配置的视觉入场提前量和用户歌词校正偏移；点击跳转使用相应逆变换。
- 换歌取消旧解析/请求结果，避免慢响应覆盖新歌曲。

交付：同一份歌词数据可驱动桌面、手机和预览；现有 YRC 链路能显示真实逐字进度。

### P2：歌词宿主与首批模式

- 新增列表视图与舞台视图：列表保留连续阅读、手动浏览和回到当前句；舞台支持整块区域构图、当前句/下一句/退场句并存。
- 定义渲染器生命周期：`mount / setDocument / update / resize / setSettings / destroy`。
- 将模式清单扩展为注册表，包含能力、加载器、默认参数、参数范围及降级模式。
- 首批升级：流光、心象、云阶、倾诉、静止；普通、AMLL、跃音同时接入新时间轴。
- 实现真实逐字填色、词语聚焦、可回放的入场/退场、长句自适应、翻译层次与间奏状态。
- 动画从歌曲时间计算，快速来回拖动进度后应回到同一画面状态。

**第一里程碑：已有音源 → YRC / LRC → 统一时钟 → 流光逐字舞台 → 桌面和手机实播。**

验收此里程碑后，再扩展其他模式，降低重复返工。

### P3：逐批补全 17 种模式

| 批次 | 模式 | 重点能力 |
| --- | --- | --- |
| 第一批，P2 完成 | 流光、心象、云阶、倾诉、静止 | 逐字时序、词语布局、句间过渡、低动态展示 |
| 第二批 | 商籁、凝彩、群唱、莫奈、回环、时计、绘光、花火 | 海报构图、色块切换、消息流、封面布局、歌词轨道、时间驱动场景和光效 |
| 第三批 | 浮名、镜台、町景、雾笺 | 镜头/空间运动、点云场景、街景层次、雾窗材质与性能降级 |

每个模式单独交付对应参数、截图/短视频和行为对照。模式之间应有独立的构图与推进方式。群唱有演唱者信息时按数据分组，没有时使用展示分组；回环要验证歌词沿轨道运动；镜台要验证真实空间和镜头效果。

逐个模式完成后替换对应旧适配版。沿用 `glow ↔ classic`、`cloud ↔ partita` 等已有 ID 映射，迁移旧设置与随机偏好。

### P4：背景、主题与声音联动

- 将背景从歌词模式中拆开，按上游能力补齐通用、隐现、莫奈、漫游、空 / Sora、嵌入背景六类。
- 实现封面取色、自定义图、主题色、模糊、遮罩、漂移与透明度；切歌过渡和模式切换可分别控制。
- 首轮复用已有 analyser 提供能量、低频/中频/高频，让光晕、粒子和缩放对音乐作出响应。
- 需要准确拍点或鼓点驱动的上游能力另建分析模块；普通频谱起伏不能充当准确节拍检测的验收结果。
- 按需启动分析，处理不可读取音频和无封面情况；音频分析不可用时仍正常播放并使用基础动效。

交付：背景与歌词可组合，声音反馈有真实输入，关闭声音联动后可独立运行。

### P5：设置、歌词来源与个性化

- 模式卡片提供实时预览、随机切换及恢复默认。
- 通用参数包含字体、字号、对齐、行距、模糊、透明度、动态强度、下一句提示、翻译和罗马音显示。
- 每种模式暴露与参考清单对应的专属参数，例如轨道半径、镜头速度、强调方式、头像和自定义图片。
- 为全局、单模式、单曲配置定义优先级；参数滑动实时预览，提交后持久化，提供配置导入/导出和版本迁移。
- 支持本地歌词导入、时间偏移校正、手动更换歌词来源、来源与精度标识、缓存刷新。
- 自动择优先校验歌曲版本/时长匹配，再比较时间精度和辅助轨道；手动选择优先，避免错误版本覆盖用户选择。

交付：效果可调、预览与实播一致，刷新后偏好和单曲修正可恢复。

### P6：性能、兼容与发布验收

- 浏览器验证覆盖 Chromium、Safari/WebKit；手机纵向、横向、桌面和全屏均检查。
- 高频更新只修改当前活动文字和场景，不逐帧重建歌词列表；排版在换句、字体和尺寸变化时测量。
- 复杂场景动态加载；限制 DPR、粒子数和后处理，提供高/中/低质量及失败降级。
- 暂停或不可见时停止持续渲染；处理 WebGL 上下文丢失；切模式释放监听器、帧循环、纹理和几何资源。
- 完成 PWA 缓存更新、资源离线策略、构建校验和现有播放功能回归。
- 在固定测试设备上记录性能。目标：桌面常规模式接近 60 fps；手机按质量档维持 30–60 fps。复杂场景以实测结果确定默认档位。

交付：可部署构建、模式完成矩阵、兼容性记录、性能报告与已知限制。

## 4. 建议文件组织

```text
js/lyrics/
  document.js             统一数据结构与校验
  parsers/                各格式适配
  clock.js                媒体时间与歌词偏移
  sources.js              来源、匹配和缓存
  runtime.js              可见性与渲染器生命周期
  registry.js             模式与能力注册
  layout/                 分词、测量、断行和布局缓存
  renderers/              普通/AMLL/跃音与 17 种舞台模式
  backgrounds/            背景、取色与声音联动
  settings.js             参数、预设及版本迁移
css/lyrics/               宿主、模式和设置样式
tests/lyrics/             格式样本、时钟、布局和交互回归
```

`index.html` 通过适配器传入音频、歌曲、歌词和设置，并接收跳转事件。旧 `lyric-effects.js` 初期充当兼容入口；旧场景按模式逐个迁移。若测试放入子目录，同步修改现有只匹配 `tests/*.test.js` 的测试命令，确保测试被执行。

## 5. 验收标准

1. 时间轴：使用已知时间戳测试词边界、停顿、长音、重叠行；可控前台测试中目标显示误差不超过 50 ms，媒体自身时间精度另行记录。
2. 播放操作：暂停不继续推进；跳转后下一可绘制帧定位正确；0.5× / 1× / 2× 播放、连续切歌、后台恢复不积累漂移。
3. 数据降级：逐字、行级、纯文本、空歌词、异常文件、未知时长、歌词加载失败均有可用状态。
4. 视觉：每个模式用同一素材对比布局、逐字推进、入退场、背景及参数。完成状态逐项标明，不能仅按“有该名称”计数。
5. 排版：中英日、emoji、长句、翻译和和声不裁字、不重叠；手机不会把英文单词随意截断。
6. 交互：点句跳转、手动浏览、返回当前句、预览、切模式、偏移设置和偏好持久化保持一致。
7. 生命周期：连续切换模式和歌曲后，无重复声音连接、残留 RAF/监听器或持续增长的 GPU 资源。
8. 回归：现有搜索、队列、音源切换、播放恢复、Bilibili 字幕、桌面/手机控制和 PWA 构建通过相应检查。

先执行阶段对应的逻辑测试和浏览器检查；最终运行现有 `npm test`、`npm run build`、`npm run check:build`，Worker 接口有改动时再运行相关 Worker 测试。

## 6. 后续扩展

歌词核心能力完成后，可继续增加 AI 主题与关键词强调、人工歌词分词修正、高精度拍点/鼓点分析、透明展示页和录制导出。每项单独定义数据来源、资源成本和验收范围。桌面专用的置顶窗口、系统壁纸和 Folium 模组需要额外的桌面宿主，属于后续独立里程碑。
