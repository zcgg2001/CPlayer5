# Android 无限音乐墙

1.16.0 预览构建（versionCode 22）将原来的分页网格改为四向无限封面墙。底部「音乐墙」入口打开后，大小交错的专辑封面一直延伸到屏幕之外。

## 交互变化

| 之前 | 现在 |
| --- | --- |
| 每页最多 36 首，上一页／下一页 | 向左、右、上、下连续浏览，没有边界或页码 |
| 规则卡片网格与单独推荐卡 | 大小封面拼贴，裁切到屏幕边缘，控件浮于封面之上 |
| 普通／密集布局切换 | 双指缩放或加减按钮调整封面大小 |
| 点歌直接操作 | 点封面展开，保留周围拼贴，再选择播放、加入队列、详情与收藏 |

手指松开后自然减速；开始下一次手势、离开音乐墙、窗口失焦或页面隐藏时停止惯性。系统启用「减少动态效果」时关闭惯性与展开动画。拖动和缩放不会误触播放。

浮动「移动音乐墙」按钮展开四向按钮，提供不必拖动的操作方式。键盘聚焦墙面后，方向键移动、加减键缩放，回车或空格展开中央高亮封面；Tab 可以直接离开墙面，不会陷入重复封面的焦点循环。Esc / Android 返回键先收起展开封面，再收起方向按钮。

「推荐」「队列」「收藏」使用现有真实歌曲数据；已有歌曲循环排列，单首歌曲也能铺满。这里的无限指浏览空间，并不表示加载了无限多首在线歌曲。空来源显示搜索或重试入口；缺图使用共享封面加载器的回退插画。正在播放的歌曲有标记，可通过定位按钮回到队列中对应的封面。

## 1.18.1 拖动响应修复

1.18.0 的封面按钮继承了 `player-base.css` 中带 `!important` 的全局 `transform 220ms` 过渡。音乐墙每帧更新目标位置，但浏览器又对这些坐标做缓动，导致封面追赶手势；新进入视口的封面也会从旧坐标滑入。

现在音乐墙封面明确关闭这层过渡，按相机坐标直接绘制，松手后的惯性仍由原有物理计算控制。歌曲标识和封面签名在数据更新时生成，不再对每块封面逐帧计算；可访问名称没有变化时也不重复改写，减少额外页面扫描。保留原有拖动阈值、点击展开、缩放和按下反馈。

回归使用 Chromium 的 4 倍 CPU 降速、连续 24 帧输入，比较实际封面矩形与应到达的相机位置：同一测试修复前偏差中位数约 10.57px、最大 16.14px；修复后最大约 0.06px。持续拖动 120px 时相机同步移动约 120px。这个指标验证消除了 CSS 插值造成的跟随偏差，不代表 Android 真机帧率或端到端触摸延迟。

`scripts/verify_android_music_wall.js` 已加入上述回归；真实触摸事件的拖动取消、双指缩放、惯性与误触抑制、远距离循环浏览、减少动态效果、横屏、大字号和深浅主题均通过，最多 59 个封面节点，无页面脚本错误。全量 104 项 Python、574 项 JavaScript、22 项 Android JVM 测试，以及站点构建检查、Android Lint 与 APK 构建通过。

安装包为 `output/android/ZPlayer-android-preview-25.apk`，版本 `1.18.1-preview` / versionCode `25`，沿用既有预览版签名。SHA-256：`70a9bac922e1887cdd4d903ad5781e42785901f87a608f2bc2a1c09375e29f33`。当前未连接 Android 设备，仍需真机确认手感和厂商 WebView 性能。

## 真实封面加载修复

排查「推荐」封面不出现时，复现了图片代理返回 502，以及部分成功请求耗时 6–8 秒、超过原来 3.5 秒图片超时的情况。旧流程只走代理，慢请求占住加载名额，失败后也不会自动补载。首次设计验收使用了本地测试封面，未覆盖这个网络问题。

现在保留代理与 Android 缓存优先，代理失败或超过 600 毫秒仍未完成时，尝试同一张、同一尺寸的公开 CDN 图片，采用先成功的结果并取消本次另一条等待。仅放行已有 CDN 白名单内无签名的公开图片；带凭据、签名参数、任意主机与账号路由不走直连。单张图片期限调整为 10 秒，每次解析仍有 12 秒总期限。Android 的直连与代理路径共用同一磁盘缓存键，页面和通知可复用相同图片。

加载队列优先处理屏幕内封面，隐藏面板不占新名额。失败封面最多自动重试两次（32 / 64 秒后），网络恢复时也可重试，离开 DOM 会取消。音乐墙右下角增加「重新加载封面」，可主动恢复失败项。不会把占位图算成加载成功。

## 实现

- `js/music-wall-field.js` 负责确定性的大小方格布局、坐标窗口、缩放锚点和惯性衰减。负坐标与很远的位置使用同一套几何，回到原位置仍对应相同封面。
- `js/music-wall.js` 只创建视口与少量周边封面，离开窗口即回收；静止时不持续请求动画帧。封面继续使用共享 `bindArtwork` 与现有缓存，避免每次滑动重复解析同图。
- `css/music-wall.css` 适配窄屏、横屏、平板、深浅主题和大字号，保留至少 48 CSS 像素的控制按钮。
- `sw.js` 更新外壳缓存并收录新增几何模块，APK 也打包相同文件。

交互参考 [myMusic 的 PosterWall](https://github.com/mytv-android/myMusic/blob/38a263531e2828e3007789a127effb3bfd398910/app/src/main/java/com/mytv/mymusic/ui/poster/PosterWall.kt) 的无限平面、大小封面与点选聚焦体验。布局和手势使用现有 WebView 独立实现，未复制该 AGPL 项目的 Kotlin 源码或原有几何模板。

## 验证

自动几何测试覆盖正负远坐标、手机／横屏／平板尺寸、缩放边界、单曲与大曲库、窗口完整覆盖、歌曲定位、回到同一位置的稳定性，以及惯性停止与缩放锚点。

`scripts/verify_android_music_wall.js` 在 Chromium 的 Android 页面中验证连续双向远距离浏览、拖动惯性与误触抑制、真实触摸事件的拖动取消及双指缩放、方向按钮与键盘、展开及返回、空来源恢复、单曲缺图、队列清空与恢复、减少动态效果、横屏操作、深浅主题和 200% 根字号。测试使用 120 首模拟记录和原创抽象测试封面，不向产品注入歌曲。当前这些场景最多同时保留 60 个封面节点，没有页面脚本错误。

`scripts/verify_android_music_wall_covers.js` 另外从网易云公开热歌榜取得真实记录，图片直接使用真实 CDN 返回的字节。在模拟图片代理全部返回 502 时，推荐首屏 **31 / 31**、远距离拖动后 **35 / 35** 可见封面均成功解码；断网到联网恢复和手动重试也分别达到 **31 / 31**，无页面脚本错误。该检查需要联网，结果只说明当时抽样的真实封面，不承诺上游永久可用。图片路由与重试逻辑另有确定性的自动回归测试。

另用本地新版界面接入本站真实推荐 API 和真实图片代理，最终可见封面 **31 / 31** 加载成功，无页面脚本错误。APK 已通过单元测试、Lint、打包内容与签名核验；签名沿用已发布预览版，可以覆盖安装。

复跑浏览器检查：

```sh
# 先在仓库根目录启动可承受模块并发请求的静态服务器
python3 -c 'import http.server; http.server.ThreadingHTTPServer.request_queue_size = 128; http.server.ThreadingHTTPServer(("127.0.0.1", 8793), http.server.SimpleHTTPRequestHandler).serve_forever()'

playwright-cli -s=infinite-wall open http://127.0.0.1:8793/offline.html --headed

playwright-cli -s=infinite-wall run-code --filename scripts/verify_android_music_wall_covers.js
playwright-cli -s=infinite-wall close
```
