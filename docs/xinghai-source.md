# 星海音源接入

2026-11-11：纳入 v1.8.0；线上发布与验收结果见 [Release](https://github.com/zcgg2001/CPlayer5/releases/tag/v1.8.0)。原始文件检查见 [接入评估](xinghai-source-review.md)。文件名写 v2.3.18，实际协议来自文件头声明的 v3.2.18。

## 使用入口与支持范围

在播放器的音乐平台中选择“网易云”或“QQ 音乐”，再选择“星海”。两者均使用现有搜索、歌词、队列和自动换源流程，音源健康度与后台开关也会自动包含新渠道。已保存的后台配置会补上新渠道，保留原有开关、优先级及配置版本。

| 渠道 | 搜索与歌词 | 播放验证 |
| --- | --- | --- |
| `xinghai-netease` | 网易云原生数字 ID，复用公开目录与歌词 | 无卡密的标准 MP3、FLAC 无损样本成功；浏览器实际播放及歌词成功 |
| `xinghai-qq` | QQ 原生 mid，复用现有 QQ 搜索与歌词 | 搜索成功；无卡密播放样本返回 403，尚未验证有授权时的播放 |

支持请求标准、极高、无损、Hi-Res。界面根据实际音频显示音质，不把请求 Hi-Res 等同于获得 Hi-Res。酷我、酷狗、咪咕和汽水仍未接入，原因见评估文档。

## 服务端配置

网易云本次样本不需要卡密。QQ 本次返回 403，不能保证仅配置卡密即可解决所有拒绝；需要有效服务授权并再次验证。

可选变量为 `XINGHAI_LICENSE`，值来自音源服务提供方。它不是 ChKSz 密钥，不在网页设置中收集。

1. Node：将值放在服务器环境变量中，或者放在未提交的 `.env` 后使用 `node --env-file=.env server.js` 启动；先运行 `npm run build`。项目运行需 Node 22.18+，本次验证使用 Node 26.12.0。
2. Cloudflare：在对应 Worker 的 Settings → Variables and Secrets 中新增 **Secret** `XINGHAI_LICENSE`。保留现有账号数据库与其他 Secret；之后按项目既有发布流程部署。
3. 在后台分别检查两个星海渠道是否启用，再用真实搜索结果验证播放。401/402/403/429 会进入现有音源冷却与自动换源流程；错误提示不会包含上游令牌或原始诊断内容。

卡密留空时会尝试匿名可用范围，不会猜测卡密、绕过授权或把私密值发送给其他渠道。

## 实现与边界

- 独立适配器 `sites/xinghai-music.js`；不执行、分发完整第三方脚本，也不移植 IP 上报与自动更新功能。
- 固定 HTTPS 接口 `yy.zddyr.top/lx/api/`；每个解析请求使用独立随机设备 ID、服务器签发令牌和 10 秒总预算。
- 只对明确的令牌失效信号刷新一次，同一个解析请求保持设备 ID。普通拒绝不会反复刷新。
- `X-Token`、可选 `X-License` 仅发给固定星海接口，认证请求不跟随重定向。没有跨请求共享令牌或待完成 I/O，也不缓存依赖授权的播放解析结果。
- 搜索、歌词继续使用已有有界公共元数据缓存。每次 `/song` 或 `/audio` 会重新取令牌与解析，因此增加了一次认证调用及少量延迟；后续若要缓存，应先确认服务端令牌与出口 IP 的绑定规则。
- 播放链接仅允许原有网易云 / QQ 音频 CDN，逐跳校验并升级为 HTTPS。同源音频代理保留 Range / HEAD，流式传输，不向 CDN 发送站点 Cookie 或星海凭据。
- 音频检查最多读取 64 字节后取消，FLAC 读取 STREAMINFO 位深和采样率；其他格式保守显示，压缩音频不会标成无损。加密流或带解密 key 的响应明确拒绝。
- 前端仅收到同源音频地址与已筛选元数据；原始签名 URL、令牌、授权详情不会出现在 JSON 中。此渠道不启用下载或离线缓存授权。

## 本次实际验收

接口与浏览器测试均通过仅用于本地诊断的公共 DNS 解析访问星海，保持原域名、TLS SNI 和证书验证；其余网络请求正常直连。没有更改系统 DNS / hosts，没有把公网 IP 或 DNS 替代逻辑写入生产代码。默认系统解析此前返回 `0.0.0.0` / `::`，真实 Cloudflare 出口连通性仍需部署时验收。
