# CPlayer 5 优化实施记录

## 2026-11-08：OP Music 公开接口接入

- 新增 OP Music 的 Apple Music、网易云、QQ 入口，接入搜索、歌词、最高音质降级与同源 Range / HEAD 播放。
- 单次创建任务、串行查询、10 秒总解析期限，只读取完成任务的最新音频地址；准备超时交给既有自动换源策略。
- 读取实际音频头识别 FLAC 采样率/位深，避免把请求 Hi-Res 或原文件 M4A 当作实际音质；严格限制 API 和媒体目标。
- 同平台共享已验证的 ID；Apple ID 保持独立，后续跨平台匹配利用任务补充的专辑和时长。
- 104 项 Python、345 项 Node、9 项 workerd 检查通过。本地及正式域名各 9 个音频样本通过；线上真实浏览器通过 OP QQ Hi-Res → 模拟断线 → 51ape QQ，并保持进度。完整过程与限制见 [OP Music 验证记录](op-music-validation.md)。
- 已部署 Worker `d6762e78-4ccb-4075-9d00-c20d5765f485`，外壳缓存 v75。

## 2026-11-08：动态换源与音质自动降级

- 增加独立播放路由，根据音源健康状况、失败冷却和真实启动耗时选择候选；默认从每个渠道支持的最高档开始。
- 同平台复用已知歌曲 ID；跨平台必须严格匹配同一录音版本，避免同名翻唱与 Live 混播。
- 解析失败、媒体解码失败、音频网络中断和连续卡顿可自动恢复，并尽量保留进度。
- 限流与认证拒绝跳过该渠道，限制单次切换预算，关闭自动模式下额外预解析。
- 修正 MP3 被上游标记为无损的显示问题，GD 支持单档解析和包含无损档的完整降级顺序。
- 线上音源测试与策略细节见 [自动播放说明](auto-playback.md)。Service Worker 更新至 v74。
- 已部署至 music.505zc.tech，版本 `4cf93df5-1f0e-46fe-a556-2e77bd2d1db3`。104 项 Python、328 项 Node、8 项 Workers 测试通过，浏览器覆盖自动换源、音质降级与保留进度恢复。

## 2026-11-08：首次使用、播放反馈与推荐加载

- 手机无歌曲时展示搜索、推荐和导入入口，隐藏占位歌曲信息、音质和无效播放控件；导入后直接显示队列。
- 新增独立 `player-experience.js` 展示解析、缓冲、浏览器阻止自动播放和播放失败状态；失败提供重试、选择音源、下一首，自动播放受阻时提供明确的开始播放按钮。
- 加入队列的提示不再提前声称播放成功。切歌时暂停旧音频，解析中的播放按钮不再重复发起命令；已开始播放后的网络缓冲仍可暂停。
- 修复手机搜索入口打开抽屉后被同一次点击关闭，以及焦点被延迟转回关闭按钮的问题。
- 推荐榜单各自完成后立即呈现；已有本地候选立即可用，首次无数据时显示骨架屏，加载完成后才显示空状态；新用户隐藏空历史区域。
- 推荐刷新增加代次检查，过期请求不会覆盖当前内容；失败时保留此前可用内容。
- Service Worker 外壳版本升级为 v73，并预缓存新增 UI 模块及样式。
- 增加推荐异步顺序、过期请求和失败切歌回归测试，提供可重复执行的真实浏览器程序 `tests/browser-experience.js`，运行方法见开发文档。

验证：104 项 Python、306 项 Node 测试及静态检查通过；构建产物、Node 服务冒烟、Cloudflare 部署 dry-run 和 8 项 workerd 测试通过。浏览器使用受控接口与真实静音 WAV 验证入口、导入、渐进加载、失败重试和自动播放恢复；390px 手机与 1440px 桌面均无横向溢出。上述浏览器回归不代表全部线上音源的可用性验证。

## 2026-09-27：发布基线与错误反馈

本轮落实优化方案中的 O1/O2 首批工程措施和 O4 的错误信息部分：

- 构建脚本每次从干净的 `dist/static`、`dist/server` 生成产物，避免旧资源残留。
- 新增 `scripts/check_build_output.py`，检查核心静态文件、Worker 文件、引用闭包和环境文件泄漏。
- 新增 `scripts/smoke_server.sh`，验证 Node 同源服务的页面路由、字体 MIME 类型和无 API 密钥时的 JSON 错误响应。
- CI 改为执行构建检查和 Node 服务冒烟，不再只用 Python 静态服务器探测页面。
- Node 服务补充 `.ttf`、`.otf` MIME 类型。
- `js/http.js` 读取受控的 `{ error: { code } }` 响应，前端将缺密钥、限流、超时、下载拒绝等状态映射为可操作的中文提示；不直接展示服务端自由文本。
- 新增构建输出和结构化错误回归测试。

验证结果：Python 104 项、Node 168 项通过；静态检查、构建产物检查和同源服务冒烟均通过。浏览器首屏可加载；无密钥时新歌请求按预期进入失败状态，不影响播放器空状态显示。

尚未完成：Tailwind 运行时移除、样式收敛、真实浏览器端到端测试和上游部署级限流。这些仍按优化方案的 P1/P2 顺序推进。

## 2026-09-27：提取音乐服务模块

继续落实 O5 的第一步：

- 新增 `js/music-service.js`，集中管理音源配置、音质配置、偏好读写、搜索、榜单、歌单、歌曲解析和歌词请求。
- 主页面通过 ES Module 引入 `MusicService`，移除原先约 150 行内联服务实现；播放、搜索和下载入口保持原有调用接口。
- 服务方法支持注入 `fetchImpl`，便于使用受控响应测试，不需要连接真实上游。
- 将旧的源码字符串测试迁移到模块边界，避免重构后必须依赖 `index.html` 内联实现细节。

本轮完成后，Python 104 项、Node 171 项通过；构建、产物检查、同源服务冒烟和浏览器页面加载均通过。浏览器验证中出现的 503 是预期的未配置音乐服务密钥状态，不是模块加载错误。

## 2026-09-27：拆分播放控制、队列状态和 IndexedDB 缓存

继续落实 O5 的核心拆分：

- 新增 `js/playback-controller.js`，集中管理播放会话、快速切歌失效、播放/暂停、音质切换、下一首预加载和空队列结束行为；页面只提供展示回调。
- 新增 `js/queue-store.js`，独立持有歌单、当前索引、播放模式、随机顺序和撤销快照；保留 `window.playlist` 作为兼容出口。
- 新增 `js/cache-store.js`，封装 `CPlayer5DB` v2 的歌单和图片缓存，增加打开/事务超时、连接关闭、写入失败和图片处理失败的降级路径；缓存异常不会阻塞播放。
- Service Worker shell cache 升级到 v52，并预缓存三个新模块；构建产物校验同步纳入模块闭包。
- 将播放并发、队列撤销、缓存请求合并/超时和旧页面运行时契约迁移到模块接口测试。

验证结果：Python 104 项、Node 177 项通过；`npm run build`、`npm run check:build`、`npm run smoke:server` 均通过。浏览器打开本地播放器和播放队列成功，无新增模块运行时错误；新歌接口因本地未配置上游密钥而按预期显示失败状态。

仍待后续：将下载会话与页面展示回调进一步收敛、补充真实音频源下的端到端切歌验证，以及移除生产环境 Tailwind 运行时依赖。
