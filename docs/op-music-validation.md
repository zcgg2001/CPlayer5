# OP Music 验证记录

接口文档：https://music.op.wiki/docs/api/ 。测试日期：2026-11-08。

新增 Apple Music、网易云、QQ 三个入口，接入已有最高音质与自动换源机制。OP Music 作为补充渠道，保留此前的 ChKSz / Meting 初始优先顺序。

## 本地真实接口采样

从本地 CPlayer 同源 API 依次搜索「晴天」「青花瓷」「稻香」，请求每个渠道的 Hi-Res，然后读取前 4 KiB 音频。最多两个渠道同时进行，不下载整首。

| 渠道 | 通过 / 样本 | 搜索至音频读取中位耗时 |
| --- | --- | --- |
| OP Music · Apple Music | 3 / 3 | 4245 ms |
| OP Music · 网易云 | 3 / 3 | 5226 ms |
| OP Music · QQ 音乐 | 3 / 3 | 11806 ms |

Apple Music 返回 16-bit / 44.1 kHz FLAC；QQ「晴天」「青花瓷」返回 24-bit / 192 kHz FLAC，「稻香」返回 Ogg；网易云包含 24-bit / 48 kHz FLAC、16-bit / 44.1 kHz FLAC 和 MP3。

只比较了渠道可用性，各平台的搜索首条不一定是同一录音。测试包括已缓存/提前准备的任务，QQ 首次创建的任务曾长时间处于 processing。10 秒准备期限用于快速转向其他音源，不会等待文档下载示例的 10 分钟。本次不是十人并发或长期稳定性测试。

## 自动化与浏览器

覆盖单次创建与串行状态查询、总等待上限、取消、错误/拒绝处理、真实格式和音质、Range / HEAD、缓存隔离、同平台 ID 与跨平台匹配、歌词，以及不安全 URL 与重定向。实际 Worker bundle 在 workerd 中验证 OP 轮询和 FLAC 流式播放。

104 项 Python、345 项 Node、9 项 workerd 测试全部通过；静态检查、产物检查、服务冒烟和 Cloudflare dry-run 通过。手机和桌面回归验证既有换源、降级、播放进度恢复、自动播放权限和布局。独立本地浏览器通过搜索入口播放 Apple Music「青花瓷」，实际音频时间推进超过 40 秒，显示无损。Apple Music 在桌面与手机搜索的平台入口均可选，390px 移动布局没有横向溢出。兼容 Apple Music 以 HTTP 400 表示“没有找到歌曲”的响应，显示空结果；其他 400 错误仍明确报错。

## 正式域名采样

部署至 `https://music.505zc.tech`，最终 Worker 版本 `d6762e78-4ccb-4075-9d00-c20d5765f485`，外壳缓存 v75。下列完整采样与真实播放在 `e4163d96-14ce-44e9-a3cf-2333c71eb6c9` 完成；最终版本仅补充搜索空结果兼容，并重新通过全部自动化检查。正式域名的 Service Worker、渠道注册表、平台选择器、播放路由均与本地文件逐字一致。

| 渠道 | 通过 / 样本 | 搜索至音频读取中位耗时 |
| --- | --- | --- |
| OP Music · 网易云 | 3 / 3 | 3016 ms |
| OP Music · Apple Music | 3 / 3 | 4591 ms |

三个渠道的实际文件规格与本地采样一致。QQ 两个 Hi-Res 样本的音频读取分别约 10.4 秒、7.1 秒，准备完成并不代表媒体一定立即响应，因此继续作为后备渠道。Apple Music 歌词接口返回成功且包含非空 LRC。完整原始结果见 [采样 JSON](op-music-probes-2026-11-08.json)。

正式域名浏览器使用独立内存偏好、静音音频验证 QQ「青花瓷」：OP Music Hi-Res FLAC 实际播放成功；在 6.34 秒处模拟网络错误，自动转至 51ape QQ 的 MP3，并继续推进至 6.555141 秒。整个恢复测试耗时约 18.1 秒，包含上游解析、媒体载入和跳转，不能保证零中断。全程没有最终播放错误，未修改用户生产歌单或持久化的渠道健康记录。

最终版本另行验证：Apple Music「华语」搜索返回 HTTP 200 空数组；「青花瓷」解析 HTTP 200、真实音质为无损 FLAC，音频 Range 返回 HTTP 206 与 `fLaC` 文件头。
